## 1. What is a Retrieval Tool?

A Retrieval Tool is the **full pipeline** that makes Retrieval-Augmented Generation (RAG) work end to end: **ingesting** source documents (chunking, embedding, indexing) ahead of time, and then, at query time, **retrieving and assembling** the right chunks into context the model can ground its answer on — with the *ingestion* side treated as a first-class, versioned, re-runnable pipeline, not a one-off script.

This is a distinct pattern from Search Tool (Pattern 05), and the difference is worth being precise about:

| Search Tool (Pattern 05) | Retrieval Tool (Pattern 09) |
|---|---|
| Focuses on the **query-time mechanics**: hybrid ranking, fusion, thresholding for a single search call | Focuses on the **whole pipeline**: how documents get chunked and indexed in the first place, *and* how retrieved chunks get assembled into a coherent context block for the model |
| Assumes an already-populated index | Owns the **ingestion pipeline** — chunking strategy, re-indexing on document updates, embedding versioning |
| Returns a flat list of ranked excerpts | Produces a **context-assembly** step: deduplicating overlapping chunks, ordering by document structure, respecting a token budget, and packaging with clear provenance |
| One tool call, one search | Often orchestrates **multiple retrieval calls across different corpora** (policy docs + case precedents + regulatory text) and merges them into one coherent context |

In short: Pattern 05 is "how do I search well." Pattern 09 is "how do I build and operate the retrieval system that Pattern 05's search call runs against, and how do I turn multiple retrieval results into a well-formed context block the model can actually use effectively" — the *engineering* of RAG as a production system, not just the query.

---

## 2. What Problem Does It Solve?

| Problem | How a Retrieval Tool (pipeline) fixes it |
|---|---|
| Naive chunking (fixed character count) splits sentences/tables mid-way, destroying meaning | Structure-aware chunking (respects headings, paragraphs, table boundaries) with overlap |
| Documents get updated; a stale index silently serves outdated policy | Ingestion pipeline is idempotent and re-runnable, with document versioning and old-chunk invalidation |
| Retrieving from multiple sources (policy + precedent + regulation) separately produces fragmented, redundant context | A context-assembly step merges, deduplicates, and orders results from multiple retrieval calls into one coherent block |
| Blindly concatenating all retrieved chunks can blow past the model's effective context budget | Explicit token-budget-aware assembly — trims lowest-relevance chunks first, never silently truncates mid-chunk |
| No way to trace "why did the model believe X" back to a specific chunk | Every chunk retains a stable `chunk_id`, source document, and version for full provenance |

## 3. Realistic Production Problem — Helios Multi-Source Retrieval Pipeline

**Context:** Pattern 05 built a single search tool over one corpus (policy chunks). In production, the Fraud Investigation Agent actually needs to draw from **three separate corpora** during a single investigation: internal fraud policy (Pattern 05's corpus), historical case precedents, and external regulatory guidance (e.g., FinCEN advisories). Each corpus has its own chunking needs (policy documents are structured with numbered sections; case write-ups are narrative prose; regulatory text has dense cross-references) and update cadence.

**The ask:** Build a `HeliosRetrievalPipeline` with two halves:

1. **Ingestion side** — `ingest_document(doc_id, corpus, raw_text, structure_hints)`: chunk a document appropriately for its corpus type, embed each chunk, and upsert into the index, automatically invalidating any prior version of that document's chunks.
2. **Retrieval + assembly side** — `retrieve_context(query, corpora, token_budget)`: run retrieval across the requested corpora, merge and deduplicate results, and assemble them into a single, clearly-sourced context block that fits within a specified token budget — this is what actually gets exposed to the agent as a tool.

## 5. Complete Request → Response Flow

### Ingestion (runs when a document is added/updated — not per agent query)

1. **New document arrives** — e.g., an updated Fraud Response Playbook v4.3 replaces v4.2.
2. **Corpus-appropriate chunking** — policy documents are split using a structure-aware chunker that respects numbered section boundaries (never splitting mid-clause), with a small overlap (e.g., last sentence of section N repeated at the start of section N+1's chunk) to preserve cross-boundary context.
3. **Embedding** — each chunk is embedded with the same model used at query time (a mismatch here silently degrades retrieval quality — a common production bug).
4. **Upsert with versioning** — new chunks are inserted tagged with `document_version="4.3"` and `is_current_version=True`.
5. **Invalidate prior version** — all chunks belonging to v4.2 are flagged `is_current_version=False` in the same transaction, so retrieval never mixes content from two versions of the same policy.

### Retrieval + Assembly (runs per agent query, this is what's exposed as the tool)

6. **Agent calls** `retrieve_context(query="account freeze policy for first-time international wire", corpora=["policy", "precedent"], token_budget=2000)`.
7. **Per-corpus search** — the pipeline runs Pattern 05's hybrid search independently against the `policy` corpus and the `precedent` corpus.
8. **Merge** — results from both corpora are combined into one candidate list, each carrying its corpus label.
9. **Deduplication** — near-duplicate chunks (e.g., the same policy quoted verbatim in both a policy doc and a case write-up) are collapsed, keeping the higher-relevance instance.
10. **Budget-aware assembly** — chunks are added to the context block in relevance order, tracking a running token estimate; once the next chunk would exceed `token_budget`, it's dropped rather than truncated mid-sentence — **partial chunks never enter the context**, since a half-sentence quote is often misleading.
11. **Provenance list** — the returned context block is accompanied by a structured list of exactly which `chunk_id`s were included, so the agent's downstream citations can be verified.
12. **Return to agent**, which now has one clean, multi-source, budget-respecting context block to reason over.

---

## 6. Why a Retrieval Tool (Full Pipeline) Is the Right Pattern Here

- **Chunking strategy is corpus-specific and matters enormously** — treating a numbered policy document and free-form narrative case notes with the same fixed-size chunker produces worse retrieval quality for both; a real pipeline needs per-corpus chunking logic.
- **Version correctness is a compliance requirement** — retrieving a mix of superseded and current policy text and letting the model reason over both is a real risk in a regulated environment; the ingestion pipeline's version-invalidation step is what prevents this.
- **Multi-corpus assembly needs deliberate engineering** — naively concatenating raw search results from three separate tool calls produces a disorganized, redundant, budget-blind context; a dedicated assembly step is what turns "three search results" into "one coherent, well-sourced brief."
- **Token-budget-aware trimming beats truncation** — silently cutting a context block off mid-token or mid-chunk can leave a dangling, misleading half-sentence; dropping whole low-relevance chunks preserves the integrity of everything that remains.

```python
"""
Helios Retrieval Pipeline — Retrieval Tool Pattern
======================================================
Full RAG pipeline: corpus-aware ingestion (chunking + embedding + version
invalidation) and multi-corpus retrieval + budget-aware context assembly,
exposed to the agent as a single retrieve_context tool.

Run:
    export ANTHROPIC_API_KEY=sk-...
    export VOYAGE_API_KEY=...
    export HELIOS_DB_URL=postgresql+asyncpg://user:pass@localhost:5432/helios
    uvicorn retrieval_pipeline:app --reload
"""

from __future__ import annotations

import logging
import re
import uuid
from datetime import date, datetime, timezone
from enum import Enum
from typing import Optional

import tiktoken
import voyageai
from fastapi import FastAPI
from langchain_core.tools import tool
from pydantic import BaseModel, Field
from sqlalchemy import text
from sqlalchemy.ext.asyncio import AsyncEngine, async_sessionmaker, create_async_engine

logger = logging.getLogger("helios.retrieval_pipeline")
logging.basicConfig(level=logging.INFO)


def audit_log(event: str, **fields) -> None:
    logger.info("AUDIT | event=%s | %s", event, fields)


_TOKENIZER = tiktoken.get_encoding("cl100k_base")


def count_tokens(text_str: str) -> int:
    return len(_TOKENIZER.encode(text_str))


# --------------------------------------------------------------------------
# 1. Corpus types and corpus-specific chunkers
# --------------------------------------------------------------------------

class CorpusType(str, Enum):
    policy = "policy"
    precedent = "precedent"
    regulatory = "regulatory"


class Chunk(BaseModel):
    chunk_id: str
    document_id: str
    document_title: str
    corpus: CorpusType
    section: Optional[str] = None
    text: str
    document_version: str


def chunk_policy_document(doc_id: str, title: str, version: str, raw_text: str) -> list[Chunk]:
    """Structure-aware: split on numbered section headings (e.g. '3.1 Title'),
    never splitting mid-section. Adds a small overlap sentence for context
    continuity across chunk boundaries."""
    section_pattern = re.compile(r"(?=^\d+\.\d*\s+[A-Z])", re.MULTILINE)
    raw_sections = [s.strip() for s in section_pattern.split(raw_text) if s.strip()]

    chunks: list[Chunk] = []
    prev_tail = ""
    for section_text in raw_sections:
        heading_match = re.match(r"^(\d+\.\d*\s+[^\n]+)", section_text)
        section_label = heading_match.group(1).strip() if heading_match else None
        body = f"{prev_tail} {section_text}".strip() if prev_tail else section_text
        chunks.append(Chunk(
            chunk_id=str(uuid.uuid4()), document_id=doc_id, document_title=title,
            corpus=CorpusType.policy, section=section_label, text=body,
            document_version=version,
        ))
        # keep the last sentence as overlap context for the next chunk
        sentences = re.split(r"(?<=[.!?]) ", section_text)
        prev_tail = sentences[-1] if sentences else ""
    return chunks


def chunk_narrative_document(
    doc_id: str, title: str, version: str, raw_text: str, target_tokens: int = 300
) -> list[Chunk]:
    """Narrative chunker for case write-ups: group paragraphs up to a target
    token size, keeping paragraph boundaries intact (never splits a
    paragraph in half)."""
    paragraphs = [p.strip() for p in raw_text.split("\n\n") if p.strip()]
    chunks: list[Chunk] = []
    current: list[str] = []
    current_tokens = 0

    for para in paragraphs:
        para_tokens = count_tokens(para)
        if current and current_tokens + para_tokens > target_tokens:
            chunks.append(Chunk(
                chunk_id=str(uuid.uuid4()), document_id=doc_id, document_title=title,
                corpus=CorpusType.precedent, section=None,
                text=" ".join(current), document_version=version,
            ))
            current, current_tokens = [], 0
        current.append(para)
        current_tokens += para_tokens

    if current:
        chunks.append(Chunk(
            chunk_id=str(uuid.uuid4()), document_id=doc_id, document_title=title,
            corpus=CorpusType.precedent, section=None,
            text=" ".join(current), document_version=version,
        ))
    return chunks


CHUNKERS = {
    CorpusType.policy: chunk_policy_document,
    CorpusType.precedent: chunk_narrative_document,
    # regulatory documents reuse the structure-aware chunker in this example;
    # in production this would have its own cross-reference-aware logic.
    CorpusType.regulatory: chunk_policy_document,
}


# --------------------------------------------------------------------------
# 2. Ingestion pipeline
# --------------------------------------------------------------------------

class HeliosRetrievalPipeline:
    def __init__(self, engine: AsyncEngine, voyage_client: voyageai.Client):
        self._engine = engine
        self._session_factory = async_sessionmaker(engine, expire_on_commit=False)
        self._voyage = voyage_client

    async def ingest_document(
        self, doc_id: str, title: str, corpus: CorpusType, version: str, raw_text: str
    ) -> int:
        chunker = CHUNKERS[corpus]
        chunks = chunker(doc_id, title, version, raw_text)

        texts = [c.text for c in chunks]
        embeddings = self._voyage.embed(texts, model="voyage-3-large", input_type="document").embeddings

        async with self._session_factory() as session:
            async with session.begin():
                # Invalidate all prior-version chunks for this document FIRST,
                # in the same transaction as inserting the new ones, so a
                # reader never sees a window with zero or duplicate coverage.
                await session.execute(
                    text("""
                        UPDATE retrieval_chunks SET is_current_version = FALSE
                        WHERE document_id = :doc_id AND document_version != :version
                    """),
                    {"doc_id": doc_id, "version": version},
                )
                for chunk, embedding in zip(chunks, embeddings):
                    await session.execute(
                        text("""
                            INSERT INTO retrieval_chunks
                                (chunk_id, document_id, document_title, corpus, section,
                                 chunk_text, document_version, is_current_version, embedding,
                                 ingested_at)
                            VALUES
                                (:chunk_id, :document_id, :document_title, :corpus, :section,
                                 :chunk_text, :document_version, TRUE, :embedding, :ingested_at)
                            ON CONFLICT (chunk_id) DO NOTHING
                        """),
                        {
                            "chunk_id": chunk.chunk_id, "document_id": chunk.document_id,
                            "document_title": chunk.document_title, "corpus": chunk.corpus.value,
                            "section": chunk.section, "chunk_text": chunk.text,
                            "document_version": chunk.document_version,
                            "embedding": str(embedding),
                            "ingested_at": datetime.now(timezone.utc),
                        },
                    )

        audit_log("document_ingested", doc_id=doc_id, corpus=corpus.value,
                  version=version, chunk_count=len(chunks))
        return len(chunks)


# --------------------------------------------------------------------------
# 3. Retrieval + multi-corpus assembly
# --------------------------------------------------------------------------

class RetrievedChunk(BaseModel):
    chunk_id: str
    document_title: str
    corpus: CorpusType
    section: Optional[str]
    text: str
    relevance_score: float


class ContextAssemblyResult(BaseModel):
    query: str
    context_block: str
    included_chunks: list[RetrievedChunk]
    excluded_for_budget: int
    total_tokens: int


class RetrievalService:
    def __init__(self, pipeline: HeliosRetrievalPipeline):
        self._pipeline = pipeline

    async def retrieve_context(
        self, query: str, corpora: list[CorpusType], token_budget: int = 2000
    ) -> ContextAssemblyResult:
        query_embedding = self._pipeline._voyage.embed(
            [query], model="voyage-3-large", input_type="query"
        ).embeddings[0]

        all_candidates: list[RetrievedChunk] = []
        async with self._pipeline._session_factory() as session:
            for corpus in corpora:
                stmt = text("""
                    SELECT chunk_id, document_title, corpus, section, chunk_text,
                           1 - (embedding <=> :query_embedding) AS similarity
                    FROM retrieval_chunks
                    WHERE is_current_version = TRUE AND corpus = :corpus
                    ORDER BY embedding <=> :query_embedding
                    LIMIT 10
                """)
                rows = (await session.execute(
                    stmt, {"query_embedding": str(query_embedding), "corpus": corpus.value}
                )).mappings().all()
                for r in rows:
                    all_candidates.append(RetrievedChunk(
                        chunk_id=r["chunk_id"], document_title=r["document_title"],
                        corpus=CorpusType(r["corpus"]), section=r["section"],
                        text=r["chunk_text"], relevance_score=round(float(r["similarity"]), 3),
                    ))

        # Deduplicate near-identical chunks (same text, keep higher score)
        deduped: dict[str, RetrievedChunk] = {}
        for c in all_candidates:
            key = c.text[:200]  # cheap near-dup key on text prefix
            if key not in deduped or c.relevance_score > deduped[key].relevance_score:
                deduped[key] = c

        ranked = sorted(deduped.values(), key=lambda c: c.relevance_score, reverse=True)

        # Budget-aware assembly: add whole chunks until budget would be exceeded
        included: list[RetrievedChunk] = []
        total_tokens = 0
        excluded_count = 0
        for chunk in ranked:
            chunk_tokens = count_tokens(chunk.text)
            if total_tokens + chunk_tokens > token_budget:
                excluded_count += 1
                continue
            included.append(chunk)
            total_tokens += chunk_tokens

        context_block = self._format_context_block(included)

        audit_log("context_assembled", query=query, corpora=[c.value for c in corpora],
                  included=len(included), excluded_for_budget=excluded_count,
                  total_tokens=total_tokens)

        return ContextAssemblyResult(
            query=query, context_block=context_block, included_chunks=included,
            excluded_for_budget=excluded_count, total_tokens=total_tokens,
        )

    @staticmethod
    def _format_context_block(chunks: list[RetrievedChunk]) -> str:
        if not chunks:
            return "No relevant context found."
        parts = []
        for c in chunks:
            source = f"{c.document_title}" + (f", {c.section}" if c.section else "")
            parts.append(f"[Source: {source} | corpus: {c.corpus.value}]\n{c.text}")
        return "\n\n---\n\n".join(parts)

# 4. Wiring + thin LangChain tool wrapper
# --------------------------------------------------------------------------

import os  # noqa: E402

_DB_URL = os.environ.get(
    "HELIOS_DB_URL", "postgresql+asyncpg://helios:helios@localhost:5432/helios"
)
_engine = create_async_engine(_DB_URL, pool_size=10, max_overflow=5, pool_pre_ping=True)
_voyage_client = voyageai.Client(api_key=os.environ.get("VOYAGE_API_KEY", "test-key"))
_pipeline = HeliosRetrievalPipeline(_engine, _voyage_client)
_retrieval_service = RetrievalService(_pipeline)


@tool
async def retrieve_context(query: str, corpora: list[str], token_budget: int = 2000) -> dict:
    """Retrieve and assemble relevant context from one or more Helios
    knowledge corpora ('policy', 'precedent', 'regulatory') for a query.
    Returns a single, source-labeled context block that fits within the
    given token budget, plus the list of chunks actually included for
    citation purposes. Always cite the document_title (and section, if
    present) shown in the [Source: ...] labels when referencing this
    context in your answer."""
    corpus_enums = [CorpusType(c) for c in corpora]
    result = await _retrieval_service.retrieve_context(query, corpus_enums, token_budget)
    return result.model_dump()

# 5. FastAPI surface
# --------------------------------------------------------------------------

app = FastAPI(title="Helios Retrieval Pipeline — Retrieval Tool Pattern")


class IngestRequest(BaseModel):
    doc_id: str
    title: str
    corpus: CorpusType
    version: str
    raw_text: str = Field(..., min_length=10)


@app.post("/retrieval/ingest")
async def ingest_endpoint(req: IngestRequest):
    chunk_count = await _pipeline.ingest_document(
        req.doc_id, req.title, req.corpus, req.version, req.raw_text
    )
    return {"doc_id": req.doc_id, "chunks_created": chunk_count}


class RetrieveRequest(BaseModel):
    query: str
    corpora: list[CorpusType]
    token_budget: int = 2000


@app.post("/retrieval/context", response_model=ContextAssemblyResult)
async def retrieve_endpoint(req: RetrieveRequest) -> ContextAssemblyResult:
    return await _retrieval_service.retrieve_context(req.query, req.corpora, req.token_budget)


@app.on_event("shutdown")
async def shutdown_event():
    await _engine.dispose()
```

## Key Takeaways

- Retrieval Tool = **the whole RAG pipeline**, not just a query — ingestion (corpus-aware chunking, embedding, version invalidation) is as important as retrieval mechanics.
- **Chunk each corpus according to its own structure** — one-size-fits-all fixed-size chunking degrades retrieval quality for structured and narrative content alike.
- **Version invalidation must be transactional** — never leave a window where zero or duplicate versions of a document are searchable.
- **Assemble, don't just concatenate** — deduplicate across corpora, rank by relevance, and respect a token budget by dropping whole low-relevance chunks rather than truncating mid-chunk.
- **Provenance travels with every chunk** — `chunk_id`, `document_title`, `section`, and `corpus` must survive all the way to the final context block for citation and audit.
